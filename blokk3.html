Célcsoport: 11–12. évfolyamos technikumi tanulók

5. tanóra – Duál stack konfigurálása (routerek, PC-k) 45 perc

🔄 0–5 perc: Ismétlés és motiváció

  • Kérdés az előző blokkból: „Mi a Link-Local cím prefixe? Mire jó?” → fe80::/10, az adott láncon belüli kommunikáció.
  • Bejelentés: „Most már eljutottunk odáig, hogy élesben is konfigurálunk. Megtanuljuk, hogyan kell egy routert és egy számítógépet IPv6-ra felkészíteni anélkül, hogy az IPv4-et eltávolítanánk. Ez a duál stack.”
  • Miért fontos a duál stack? „A világ nem egyik napról a másikra tér át IPv6-ra – a következő 10-20 évben is együtt él a két protokoll.”

🧠 5–15 perc: Duál stack elméleti alapok

  • Definíció: Az eszköz egyszerre támogatja az IPv4 és IPv6 protokollvermet. Mindkét stack függetlenül fut, saját címekkel, routing táblával.
  • Hogyan dönt az alkalmazás?
    • Általában az operációs rendszer preferenciája: IPv6 előnyben, ha elérhető (RFC 6724, „Happy Eyeballs”).
    • Pl. webböngésző először megpróbálja az IPv6-ot, ha nem megy, átvált IPv4-re.
  • Címzés duál stack esetén:
    • Egy interfészhez több cím is tartozhat: IPv4, IPv6 Link-Local, IPv6 GUA/ULA.
    • Pl. ip addr show Linuxon: látni fogod az IPv4 mellett az IPv6-okat.
  • Előnyök: Fokozatos átállás, kompatibilitás, nincs szükség tunnel protokollokra (bár az is létezik).
  • Hátrány: Két párhuzamos stack kezelése = kétszeres konfiguráció, több erőforrás, kétszer annyi routing bejegyzés.

🏗️ 15–30 perc: Topológia építése (Packet Tracer vagy közös bemutató)

  • Közös munka: (oktató által vezetve, diákok követik saját gépükön)
  • Topológia:
    • 2 router: R1, R2 (Cisco 2911)
    • 2 PC: PC1 (csatlakozik R1-hez), PC2 (csatlakozik R2-höz)
    • R1 és R2 összekötve egy pont-pont kapcsolattal
  • Kapcsolatok és címek: 
    PC1 (eth0) ---- (g0/0) R1 (g0/1) ---- (g0/0) R2 (g0/1) ---- PC2 (eth0)

IPv4:
PC1:   10.0.1.2/24, GW 10.0.1.1
R1 g0/0: 10.0.1.1/24
R1 g0/1: 10.0.12.1/24
R2 g0/0: 10.0.12.2/24
R2 g0/1: 10.0.2.1/24
PC2:   10.0.2.2/24, GW 10.0.2.1

IPv6 (GUA):
PC1:   2001:db8:1::2/64, GW 2001:db8:1::1
R1 g0/0: 2001:db8:1::1/64
R1 g0/1: 2001:db8:12::1/64
R2 g0/0: 2001:db8:12::2/64
R2 g0/1: 2001:db8:2::1/64
PC2:   2001:db8:2::2/64, GW 2001:db8:2::1
  • Táblán vagy projektoron a topológia rajza.

⚙️ 30–40 perc: Router konfiguráció lépésről lépésre (Cisco)

  • Minden routeren először: 
    enable
configure terminal
ipv6 unicast-routing   ! EZ NÉLKÜL NINCS IPv6 ROUTING!
  • R1 konfig: 
    interface g0/0
 ip address 10.0.1.1 255.255.255.0
 ipv6 enable
 ipv6 address 2001:db8:1::1/64
 no shutdown
interface g0/1
 ip address 10.0.12.1 255.255.255.0
 ipv6 enable
 ipv6 address 2001:db8:12::1/64
 no shutdown
end
write memory
  • R2 konfig (hasonló, szimmetrikus): 
    interface g0/0
 ip address 10.0.12.2 255.255.255.0
 ipv6 enable
 ipv6 address 2001:db8:12::2/64
 no shutdown
interface g0/1
 ip address 10.0.2.1 255.255.255.0
 ipv6 enable
 ipv6 address 2001:db8:2::1/64
 no shutdown
end
write memory
  • Fontos parancsok magyarázata:
    • ipv6 enable – bekapcsolja az IPv6-ot az interfészen (automatikusan generál egy Link-Local címet is).
    • ipv6 address .../64 – statikus GUA hozzárendelése.
    • no shutdown – interfész aktiválása (alapból le van tiltva).
  • Ellenőrzés:
    • show ipv6 interface brief – listázza az összes IPv6 címet.
    • show ipv6 route – IPv6 routing tábla (még nincs útvonal, csak a közvetlen kapcsolatok).

🖥️ 40–45 perc: PC-k konfigurálása (Windows/Linux példák)

  • PC1 (Windows – CLI vagy GUI): 
    netsh interface ip set address "Ethernet0" static 10.0.1.2 255.255.255.0 10.0.1.1
netsh interface ipv6 set address "Ethernet0" static 2001:db8:1::2/64
netsh interface ipv6 add route ::/0 "Ethernet0" 2001:db8:1::1
    Az alapértelmezett útvonal megadása kötelező, mert a router nem küld még RA-t (később a SLAAC-nál majd automatikus).
  • PC1 (Linux – ip parancsokkal): 
    sudo ip addr add 10.0.1.2/24 dev eth0
sudo ip route add default via 10.0.1.1
sudo ip -6 addr add 2001:db8:1::2/64 dev eth0
sudo ip -6 route add default via 2001:db8:1::1
  • Megjegyzés: A PC Link-Local címén keresztül is megadhatnánk a gateway-t (fe80::1), de a GUA gateway egyszerűbb a kezdeti tanuláshoz.
  • Ellenőrzés PC-n: ipconfig (Windows) vagy ip -6 addr show (Linux) – látszik a GUA és a Link-Local is.
  • Házi feladat előzetes: „Ellenőrizzétek, hogy a ping6 működik-e a következő órán – addig ne is lépjetek tovább!”

6. tanóra – Ping6, traceroute6, statikus routing 45 perc

🔄 0–5 perc: Ismétlés a konfigurációból

  • Kérdés: „Ki tudja fejből mondani, hogy kell egy Cisco interfészre IPv6 címet adni?” → ipv6 address 2001:db8:1::1/64
  • „Mi a különbség az ipv6 enable és az ipv6 address között?” → ipv6 enable csak Link-Localt ad, az ipv6 address ad GUA-t is.
  • Ellenőrizzük közösen, hogy mindenki eljutott-e a konfiguráció végéig. (Ha Packet Tracerben dolgoznak, néhány perc javítás.)

📡 5–15 perc: Ping6 és Traceroute6 – Alapvető hibakeresés

  • Ping6 a közvetlen kapcsolatokon belül:
    • PC1-ről pingeljük a saját gatewayt: ping 2001:db8:1::1 (Windows/Linux egyaránt működik). Ha nem megy, ellenőrizzük a fizikai kapcsolatot, az interfész állapotát (no shutdown), a tűzfalat (Windows tűzfal néha blokkolja).
    • PC1-ről pingeljük a R1 másik interfészét (g0/1): ping 2001:db8:12::1 – ennek mennie kell, mert ugyanazon a routeren belül van.
    • PC1-ről pingeljük a R2 g0/0-át: ping 2001:db8:12::2 – ennek is mennie kell, mert a router továbbítja a pinget? Nem! Még nincs statikus útvonal a routerek között, és a PC sem tudja, merre van a 2001:db8:2::/64. De a PC pingje a 2001:db8:12::2-t eléri, mert az a R2 egyik interfésze, és a R1 tudja, hogy az a 2001:db8:12::2 közvetlen elérhető.
  • Traceroute6:
    • Windows: tracert -6 2001:db8:2::2
    • Linux: traceroute6 2001:db8:2::2
    • Elsőként látni fogjuk, hogy a csomag megáll a R1-nél, mert nem tud továbbmenni.
  • Eszközök a routeren a hibakereséshez:
    • debug ipv6 icmp – látjuk a ping kéréseket és válaszokat (óvatosan, éles rendszeren ne).
    • show ipv6 interface – ellenőrizzük, hogy az interfész „up/up”.
    • show ipv6 neighbors – NDP cache (hasonló az ARP cache-hez).

🛤️ 15–30 perc: Statikus útvonalak IPv6-ban

  • Probléma: A R1 tudja, hogyan érje el a 2001:db8:1::/64-et (saját interfész) és a 2001:db8:12::/64-et, de a 2001:db8:2::/64-et nem. A R2 hasonlóan nem ismeri a PC1 hálózatát.
  • Megoldás: Statikus útvonalak felvétele mindkét routeren.
  • Parancs a R1-en: 
    ipv6 route 2001:db8:2::/64 2001:db8:12::2
    Ez azt jelenti: „A 2001:db8:2::/64 hálózatot a 2001:db8:12::2 (R2 g0/0 címe) felé tudom elérni.”
  • Parancs a R2-n: 
    ipv6 route 2001:db8:1::/64 2001:db8:12::1
  • Alternatív megadás Link-Local címmel (említés szintjén): 
    ipv6 route 2001:db8:2::/64 g0/1 fe80::2
    Ez akkor jó, ha a következő hop Link-Local címét használjuk. Előny: nem kell megváltoztatni a GUA címet. Hátrány: bonyolultabb kezdőknek.
  • Ellenőrzés: show ipv6 route – most már látjuk a S (static) bejegyzéseket.
  • Visszatérve a pinghez:
    • PC1-ről ping 2001:db8:2::2 – sikeres kell legyen!
    • Közben tracert -6 2001:db8:2::2 mutatja az utat: PC1 → R1 → R2 → PC2.

👥 30–40 perc: Gyakorlás – Kisebb csoportos feladat

  • Feladat: A topológiát már megépítették. Adják hozzá a statikus útvonalakat, majd ellenőrizzék a pinget minden irányban (PC1 → PC2, PC2 → PC1, valamint PC-k pingeljék a másik router interfészeit).
  • Kiegészítő feladat gyorsabbaknak: Távolítsák el az alapértelmezett gateway-t a PC1-ről, és helyette adjanak hozzá egy specifikus útvonalat a 2001:db8:2::/64 felé a R1 Link-Local címén keresztül. (Nehezebb, de mélyíti a megértést.)
  • Körbejárás, segítségnyújtás.

📌 40–45 perc: Összefoglalás, házi feladat, előzetes a 4. blokkhoz

  • Összefoglaló kérdések:
    • „Mi a duál stack lényege?” → Két protokoll verem együtt.
    • „Milyen paranccsal nézzük meg az IPv6 routing táblát Cisco-n?” → show ipv6 route
    • „Hogyan pingelünk IPv6-ra?” → ping vagy ping6 (a platformtól függ).
  • Házi feladat (írásban vagy Packet Tracer fájl beküldéssel):
    „Egészítsd ki a mai topológiát egy harmadik routerrel (R3) és egy PC3-mal. R2 és R3 közé vegyél fel egy új /64-es hálózatot (2001:db8:23::/64). Állítsd be a címeket és a statikus útvonalakat úgy, hogy PC1 pingelni tudja PC3-at is. Add meg az összes szükséges ipv6 route parancsot.”
  • Előzetes a következő órára: „A statikus címzés után következik a dinamikus. Megtanuljuk, hogyan kaphatnak a PC-k automatikusan IPv6 címet anélkül, hogy DHCP szervert kellene telepíteni – ez a SLAAC. Hozzatok magatokkal jegyzetet a következő elméleti részhez.”

💡 Parancsgyűjtemény (kiosztható segédlet a 3. blokkhoz)
Cisco:
ipv6 unicast-routing – globálisan bekapcsolja az IPv6 routingot
ipv6 enable – interfészen engedélyezi az IPv6-ot (Link-Local)
ipv6 address <cím>/<prefix> – statikus GUA
show ipv6 interface brief – IPv6 interfészek listája
show ipv6 route – IPv6 routing tábla
show ipv6 neighbors – NDP cache
ipv6 route <cél/prefix> <következő hop> – statikus útvonal
Windows:
netsh int ipv6 set address "Eth" static <cím>
netsh int ipv6 add route ::/0 "Eth" <gw>
ping -6 <cím>
tracert -6 <cím>
Linux:
ip -6 addr add <cím>/<prefix> dev eth0
ip -6 route add default via <gw>
ping6 <cím>
traceroute6 <cím>
⚠️ Gyakori hibák és megoldásuk a 3. blokkban
  • Hiba: PC1-ről nem megy a ping a gatewayre (2001:db8:1::1)
    Ok: Tűzfal blokkolja (Windows), vagy rossz a gateway cím
    Javítás: Kapcsold ki a tűzfalat tesztelésre; ellenőrizd az IPv6 címet a PC-n
  • Hiba: A routerek egymást nem pingelik a pont-pont kapcsolaton
    Ok: ipv6 unicast-routing hiányzik; vagy az egyik interfész le van állítva (shutdown)
    Javítás: Ellenőrizd a konfigot, add hozzá a parancsot
  • Hiba: show ipv6 route nem mutatja a közvetlen hálózatokat
    Ok: Az interfészen nincs ipv6 enable vagy nincs cím
    Javítás: Add hozzá, majd no shutdown
  • Hiba: A ping a távoli PC-re (2001:db8:2::2) nem megy, de a közbülső router interfészek igen
    Ok: Hiányzik a statikus útvonal az egyik routeren
    Javítás: Ellenőrizd mindkét router routing tábláját
📚 Differenciálási lehetőségek (3. blokk)
  • Gyengébbeknek: Adjunk kész konfigurációs sablont, amit csak be kell másolni. A ping és traceroute parancsokat lépésről lépésre közösen végezzük.
  • Erősebbeknek: Próbálják ki a Link-Local alapú statikus routingot (ipv6 route ... g0/1 fe80::2). Valamint próbálják meg a duál stack mellett az IPv4 routingot is beállítani (statikus vagy RIP). Készítsenek Wireshark felfogást és elemezzék az NDP csomagokat.
🔍 Linux extra parancsok a 3. blokkhoz:
ip -6 route show – IPv6 routing tábla
ip -6 neigh show – NDP cache
ping6 -I eth0 fe80::1 – ping egy link-local címre a megadott interfészen keresztül
traceroute6 -n 2001:db8:2::2 – útvonal követés névfeloldás nélkül
